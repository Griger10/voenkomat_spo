# WPF-приложение

Реализован по [Figma, узел 1:2](https://www.figma.com/design/buU9TzTG3NbO9lhwRvPnrM/TRPO?node-id=1-2).
Эмблема и семь оригинальных SVG получены через локальный Figma MCP, находятся
в `Assets`; SVG отображаются через SharpVectors.Wpf. Шрифты Inter Regular,
Inter SemiBold и JetBrains Mono Medium встроены в приложение. Лицензии — в `Assets/Fonts`.

## Запуск

Из корня репозитория:

```powershell
docker compose up -d database
dotnet ef database update --project src/VoenkomatSpo.Infra
dotnet run --project src/VoenkomatSpo.WPF
```

Приложение и `dotnet ef` используют общую настройку подключения в Infra:
`.env` ищется в текущей директории и выше, затем около исполняемого файла и выше.
Переменные процесса имеют приоритет. Для запуска опубликованной программы
разместите `.env` около `.exe` или задайте переменные процесса.

Демонстрационный вход: `admin.demo` / `DemoOnly!2026`.
Другие учебные логины: `ivanova.demo`, `petrov.demo` (специалисты воинского учёта),
`smirnova.demo` (учебная часть), `observer.demo` (наблюдатель).
У них тот же демонстрационный пароль.

## Слои

- **Core/Authentication**: контракт авторизации, результат с ролью и правами,
  интерфейсы хеширования и хранилища сохранённых данных.
- **Infra/Authentication**: EF-запрос пользователя и роли, проверка PBKDF2-SHA256,
  обновление `last_login_at` и запись `ActionLog` одним `SaveChangesAsync`.
  При неверных данных изменения в БД не производятся. Для неизвестного логина
  также выполняется проверка хеша; запросы параметризованы EF Core.
- **WPF/ViewModels**: `LoginViewModel` с `ObservableProperty` и `RelayCommand`
  из CommunityToolkit.Mvvm. Валидация, состояние загрузки, отмена, ошибки,
  показ пароля, восстановление входа и выход.
- **WPF/Views, Controls, Styles**: XAML и оформление. Code-behind содержит
  только жизненный цикл окна и синхронизацию `PasswordBox` с привязкой.
  Компоновка зависимостей находится в `App.xaml.cs`.

Enter отправляет форму. Пока выполняется вход, поля и повторная отправка
заблокированы. Пароль скрыт по умолчанию и очищается после неверного или
успешного входа. Начальный размер окна — 1296 × 881, размер можно менять вручную.
Если форма не помещается, появляется вертикальная прокрутка.

«Запомнить меня» сохраняет учётные данные на 30 дней в
`%LOCALAPPDATA%/VoenkomatSpo/credentials.dat`, зашифрованные Windows DPAPI
для текущего пользователя ([документация Microsoft](https://learn.microsoft.com/en-us/dotnet/standard/security/how-to-use-data-protection)).
При следующем запуске они повторно проверяются в БД; сохранённый файл
сам по себе не предоставляет доступ. Выход удаляет сохранённые данные.

После успешного входа открывается окно «Документы для военкомата».
Подпись о ГОСТ оставлена из макета; она не означает реализованное
ГОСТ-шифрование. Его необходимо обеспечивать отдельной инфраструктурой.
Версия, адрес поддержки и законодательная подпись также взяты из макета.

## Проверки

```powershell
dotnet test
# Дополнительно: требуется запущенный PostgreSQL и право CREATE DATABASE.
$env:VOENKOMAT_POSTGRES_TESTS = '1'
dotnet test
```

Интеграционные проверки документов создают БД с уникальным именем
`voenkomat_documents_test_*`, применяют миграции и затем удаляют только свою
тестовую БД. Основная БД не изменяется. Проверка подготовки к печати использует
встроенный PDF-движок Windows без отправки документа на принтер.

## Документы для военкомата

Экран реализован по [Figma, узел 1:1443](https://www.figma.com/design/buU9TzTG3NbO9lhwRvPnrM/TRPO?node-id=1-1443).
Оригинальные SVG находятся в `Assets/Documents`.

- Форма № 10 формируется для выбранного студента с действующей карточкой.
  PDF содержит ФИО, дату рождения, группу, личное дело, адрес, паспортные данные,
  комиссариат и сведения о воинском учёте.
- Форма № 6 формируется за выбранный год для одного или всех комиссариатов.
  Включаются карточки студентов, зачисленных не позднее конца выбранного года
  и не снятых с учёта до этой даты. Категории и другие сведения берутся из
  текущих данных системы. PDF содержит сводные показатели, распределение
  по комиссариатам и перечень студентов.
- Это базовые информационные PDF с указанием номера формы, а не официальные
  унифицированные бланки. Шрифты Inter встроены в файлы; установка шрифтов
  на компьютере получателя не требуется.
- В БД хранятся реквизиты документа, имя файла, статус сверки и дата представления.
  PDF сохраняется отдельным файлом в `%LOCALAPPDATA%/VoenkomatSpo/Documents`.
  Папку можно переопределить переменной `DOCUMENTS_PATH` в `.env` или окружении.
  Для нескольких рабочих мест укажите общую папку, доступную всем этим местам.
  PDF сохраняется при формировании, поэтому изменение студента не меняет исходный файл.
  Отмена диалога сохранения не удаляет сформированный документ из журнала.
- Журнал поддерживает поиск без учёта регистра по ФИО, номеру и сведениям,
  фильтры формы, года, комиссариата и статуса. На странице от 1 до 4 записей:
  количество автоматически подбирается по высоте таблицы, включая открытые фильтры.
  Экспорт журнала учитывает фильтры и включает все найденные страницы.
- В строке доступны открытие, скачивание PDF и меню «⋯»: печать, подтверждение
  сверки, отметка фактического представления. Печать использует стандартный
  диалог Windows и встроенный PDF-движок; отдельный PDF-просмотрщик для неё
  не нужен. Для открытия PDF используется приложение, выбранное в Windows.
- Отметка представления доступна после сверки и требует подтверждения.
  Она фиксирует дату фактической передачи, но не отправляет документ в ВК.
  Повторное подтверждение уже представленного документа не создаёт повторных
  записей аудита. Одновременные изменения статуса защищены проверкой конкуренции.
- `cards.write` разрешает создавать и изменять статус формы № 10;
  `reports.write` — формы № 6. Чтение определяется `cards.read` и `reports.read`.
  Права повторно проверяются сервисом по роли в БД. Формирование, сверка и
  представление записываются в `ActionLog`.

`ShellViewModel` переключает вход и документы; `DocumentsViewModel` управляет
формой и журналом; контракты находятся в Core/Documents, реализация сервиса
и PDF — в Infra/Documents, файловые диалоги и печать — в WPF/Services.
Целевая платформа WPF — Windows 10 версии 2004 или новее.
Другие разделы бокового меню отключены; «Мои данные», помощь, сводка уведомлений,
обновление и выход работают в пределах этого окна. После первой миграции
журнал пуст: в нём появляются действительно сформированные PDF.

Окно документов открывается размером до 1440 × 960 с ограничением по рабочей
области экрана. Используется компактная сеточная компоновка без полос прокрутки:
все столбцы и действия доступны сразу, длинные значения сокращаются и показываются
в подсказках. Минимальный размер зависит от доступного места на экране.

## Обновление старой БД с PDF

Для переноса уже сохранённых в БД PDF используйте из корня репозитория:

```powershell
dotnet run --project tools/VoenkomatSpo.DbUpdate
```

Утилита сначала выгружает существующие PDF в папку документов, затем применяет
миграции. Миграция `MoveDocumentPdfsToFiles` проверяет выгрузку и удаляет столбец
`pdf_data`; она не разрешит удаление невыгруженных файлов. Для новой БД без документов
по-прежнему подходит `dotnet ef database update --project src/VoenkomatSpo.Infra`.
Перенос бинарных данных необратим обычным откатом миграции: восстановление старой
схемы требует резервной копии. Резервируйте БД вместе с папкой PDF.
